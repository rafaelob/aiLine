Plugins, Skills & MCP em Frameworks

Como colocar um plugin completo (skills + MCP), só uma skill ou só um servidor MCP dentro do seu próprio processo — Google ADK, OpenAI Agents SDK, LangChain, LangGraph, Deep Agents e Claude Agent SDK. Este guia cobre exclusivamente integração self-hosted: skills lidas do seu filesystem, servidores MCP que você roda (stdio / Streamable HTTP). Não cobre Skills hospedadas pela API do provedor, MCP remoto executado pelo provedor ou connectors — esses aparecem só para contraste, com link para onde são tratados.

3. Faça / Não faça

  • Não confunda "plugin": bundle (skills + MCP), plugin de host (Claude Code) e hook de lifecycle (BasePlugin do ADK, AgentHooks/RunHooks do Agents SDK) são objetos diferentes.
  • Não use langchain-mcp-adapters (repositório arquivado em 2026-09-16, 0.3.2, mcp<2) → langchain.mcp.MCPAdapter.
  • MCPAdapter("...") com string só aceita URL; para servidor stdio passe Path("server.py").
  • Agents SDK: skills só dentro de SandboxAgent; o mantenedor não planeja skills para agentes comuns (issue #5025, fechada em 2026-09-17). Fora do sandbox use o loader manual. Em JS/TS trate como não suportado.
  • Deep Agents: para recarregar skills use {"skills_metadata": None}, nunca [] (lista vazia = "nenhuma skill existe"). Recarga exige deepagents ≥ 0.7.16 / JS 1.14.0.
  • Claude Agent SDK: o padrão de query() carrega as fontes user e project; um setting_sources explícito sem elas desativa as skills (ver Armadilhas); a opção skills ("all"/lista/[]) adiciona a tool Skill sozinha, mas com lista tools explícita inclua "Skill"; tools MCP são mcp__<server>__<tool> e exigem allowlist; plugins[].type só aceita "local".
  • ADK: BasePlugin usa tool_args (não args) e parâmetros somente nomeados. Skills do ADK são Experimental; o gate "v1.25.0+" é da linha 1.x.
  • Microsoft Agent Framework 1.19.0: use Agent (não ChatAgent) e static_headers= (não headers=). Pydantic AI: MCPToolset, não as classes antigas por transporte.
  • Nenhum framework deste guia documenta carregador nativo do formato agent-plugins.org; Claude Code plugin (.claude-plugin/plugin.json) e Agent Plugins (plugin.json na raiz) têm schemas distintos.
  • Tratar plugin de terceiro como supply chain: fixe versão/commit, revise hooks/hooks.json e .mcp.json/mcp.json, use --plugin-url só com arquivo que você controla. Agent Plugins 1.0.0 não define permissão, sandbox nem assinatura. Sem credencial em headers do mcp.json.
  • O nível de isolamento de scripts de skill varia por framework; só Sandbox Agents da OpenAI o documenta como isolado (ver Segurança).

Sobre este guia & fronteira

"Integrar um plugin" pode significar três coisas bem diferentes, e a primeira armadilha é confundi-las. Este guia trata da terceira: você tem um plugin, uma skill ou um servidor MCP em disco (ou como processo que você inicia), e quer que um agente construído com um framework os use — sem depender de nenhuma infraestrutura hospedada pelo provedor do modelo.

CenárioOnde rodaCobertura
Self-hosted (este guia) No seu processo/infra: SKILL.md lido do seu filesystem; servidor MCP que você inicia via stdio (subprocesso local) ou aponta via Streamable HTTP (seu ou de terceiros, mas conectado pelo seu cliente MCP). Google ADK, OpenAI Agents SDK, LangChain, LangGraph, Deep Agents, Claude Agent SDK — matriz na §2, receitas nas §3–8.
Skills hospedadas (Claude API) Executadas dentro do container de code execution da própria Anthropic (container.skills[]); você faz upload via Skills API, não lê do seu disco. Fora de escopo — ver guia_claude_api.html#c-skills.
Skills hospedadas (OpenAI) A tool skills da Responses/Agents API roda dentro do hosted shell da OpenAI — diferente da Skills capability self-hosted do Agents SDK (§4), que roda no seu próprio sandbox local. Fora de escopo — ver guia_agents_sdk.html#s-tools-hosted-shell-skills.
MCP remoto executado pelo provedor Ex.: HostedMCPTool (OpenAI) ou os hosted MCP server tools do Claude API — a chamada da tool MCP acontece do lado do provedor, não do seu processo. Fora de escopo — ver guia_claude_api.html#c-remote-mcp e guia_agents_sdk.html#s-mcp-hosted.
Connectors (Claude, ChatGPT) Integrações pré-configuradas e geridas pelo provedor/organização (Slack, Google Drive etc.), não um servidor MCP que você aponta. Fora de escopo deste guia.

Cada afirmação de suporte nativo cita a página oficial ou o código-fonte da versão citada; onde a doc não confirmou, o texto diz "não verificado" em vez de inventar a assinatura.

"Plugin" tem três sentidos diferentes — e eles colidem

Antes da matriz: a palavra "plugin" aparece em pelo menos três objetos distintos nesta área, e dois frameworks cobertos aqui usam o mesmo nome para o sentido errado do ponto de vista de quem pergunta "como coloco um plugin no meu agente".

  1. Bundle portátil cross-vendor — o que a pergunta do usuário quer dizer por "um plugin (com MCP e skill)": uma pasta com um manifest, uma pasta skills/ no formato Agent Skills e um mcp.json declarando servidores MCP. É o que agent-plugins.org padroniza como plugin.json + skills/ + mcp.json, e é também o que o formato de plugin do Claude Code já implementava antes (skills + MCP + hooks + agents) — ver §8.
  2. Plugin de host/CLI — a implementação concreta que um cliente específico carrega (Claude Code plugin, dcode plugin). Historicamente anterior ao padrão aberto, com schema próprio que não é byte-idêntico ao de agent-plugins.org v1.0.0 (campos e nomes de arquivo diferem; ver §1) mas cobre a mesma ideia.
  3. Hook de lifecycle do próprio SDK — sentido completamente diferente, sem relação com skills ou MCP. O BasePlugin do Google ADK (§3) e os AgentHooks/RunHooks do OpenAI Agents SDK (§4) são instrumentação: callbacks before_agent/after_model/before_tool etc. registrados no Runner/na sessão, para logging, guardrails, retry — não um pacote de capacidades que você instala.
Armadilha de nome nº 1. Se você procurar "ADK plugin" esperando um pacote instalável de skills+MCP, vai encontrar BasePlugin — que é o sentido 3, não o sentido 1. Nada no ADK se chama "plugin" no sentido 1; o mecanismo equivalente lá chama-se SkillToolset (skill) + McpToolset (MCP), sem um envelope de "plugin" que amarre os dois — ver §3.

1. O bundle cross-vendor: agent-plugins.orgAtualizado · 2026-09-30

agent-plugins.org publica a Agent Plugins Specification 1.0.0 (status "Published"): "an open, vendor-neutral standard for packaging reusable components into portable plugins", unindo Agent Skills e servidores MCP num único formato de pasta. O Technical Steering Committee reúne Core Maintainers de Amazon, Cursor, Microsoft, OpenAI e Vercel. Um working draft 1.1.0 existe no repositório da spec desde 2026-08-12 (agentplugins/agent-plugins-spec), sem release: o contrato vigente é o 1.0.0. Verificado em 2026-09-30 em agent-plugins.org/specification e no guia de Skills §6C, que traz o schema completo. 

my-plugin/
├── plugin.json          # obrigatório: $schema + name (schema fechado)
├── skills/              # opcional: cada subpasta imediata com SKILL.md (formato Agent Skills)
│   └── summarize/
│       ├── SKILL.md      # ver guia_skills.html
│       ├── scripts/
│       └── references/
├── mcp.json              # opcional: {"$schema": ..., "mcpServers": {...}}
└── com.example.client/   # namespace reverse-domain: dados específicos de um cliente

Em mcp.json, cada servidor declara type: stdio (command com um único token executável, mais args/env/cwd), streamable-http (url, headers opcional) ou sse (legado, suporte opcional do cliente). Não há campo portátil de credencial: headers são dados literais do pacote. Distribuição, instalação, permissões e capacidades específicas de cliente ficam sob controle de cada cliente; a 1.0.0 não define modelo de permissão, sandbox nem assinatura (ver §10).

Clientes compatíveis (leitura de 2026-09-23; a página é dinâmica e não foi relida em 2026-09-30, UNVERIFIED): agent-plugins.org/compatible-clients listava NanoClaw, ChatGPT & Codex, OpenHands, Cursor, OpenClaw, Grok Bot, Hermes Agent, Kiro, VS Code e GitHub Copilot. Nenhum dos frameworks de biblioteca deste guia aparece: a lista é de clientes/hosts, não de SDKs. A Anthropic não aparece entre mantenedores nem clientes; o formato de plugin do Claude Code (§8, .claude-plugin/plugin.json) é distinto e a spec não declara interoperabilidade com ele (verificado em 2026-09-30).

Nenhum dos frameworks cobertos documenta um carregador nativo para o formato agent-plugins.org (verificado nas páginas oficiais de cada um em 2026-09-23 e 2026-09-30). O padrão manual da §Templates lê o bundle e conecta suas duas partes (skills, MCP) às APIs nativas de cada framework: é uma receita desta coleção, não API de framework.

MCP — McpToolset

Fonte: adk.dev/tools-custom/mcp-tools (antes em google.github.io/adk-docs), acessado 2026-09-23; a assinatura de McpToolset usada abaixo não mudou no wheel 2.10.0. 

import os
from google.adk.agents import LlmAgent
from google.adk.tools.mcp_tool import McpToolset
from google.adk.tools.mcp_tool.mcp_session_manager import StdioConnectionParams
from mcp import StdioServerParameters

TARGET_FOLDER_PATH = os.path.join(os.path.dirname(os.path.abspath(__file__)), "data")

root_agent = LlmAgent(
    model="gemini-flash-latest",
    name="filesystem_assistant_agent",
    instruction="Help the user manage their files.",
    tools=[
        McpToolset(
            connection_params=StdioConnectionParams(
                server_params=StdioServerParameters(
                    command="npx",
                    args=["-y", "@modelcontextprotocol/server-filesystem", TARGET_FOLDER_PATH],
                ),
            ),
            # tool_filter=["list_directory", "read_file"],  # opcional — allowlist de tools
        )
    ],
)
import os
from google.adk.agents.llm_agent import Agent
from google.adk.tools.mcp_tool import McpToolset
from google.adk.tools.mcp_tool.mcp_session_manager import StreamableHTTPConnectionParams

root_agent = Agent(
    model="gemini-flash-latest",
    name="travel_planner_agent",
    tools=[
        McpToolset(
            connection_params=StreamableHTTPConnectionParams(
                url="https://mcp.example.com/mcp",
                headers={"Authorization": f"Bearer {os.environ['MCP_TOKEN']}"},
            )
        )
    ],
)

Skill — SkillToolset + load_skill_from_dir

Fonte: adk.dev/skills, acessado 2026-09-23 (o wheel 2.10.0 foi inspecionado em 2026-09-30). A própria página cita textualmente o gate de versão e o status: "Supported in ADK Python v1.25.0 · TypeScript v0.6.1 · Go v1.2.0 · Kotlin v0.1.0 · Experimental" e reforça: "The Skills feature is experimental." 

import pathlib
from google.adk import Agent
from google.adk.skills import load_skill_from_dir
from google.adk.tools import skill_toolset

weather_skill = load_skill_from_dir(
    pathlib.Path(__file__).parent / "skills" / "weather_skill"
)

my_skill_toolset = skill_toolset.SkillToolset(
    skills=[weather_skill],
    additional_tools=[get_weather_tool],  # tools normais podem coexistir
)

root_agent = Agent(
    model="gemini-flash-latest",
    name="skill_user_agent",
    instruction="You are a helpful assistant that can leverage skills.",
    tools=[my_skill_toolset],
)
Versão confirmada (2026-09-30). O gate publicado ("v1.25.0+") é da linha 1.x; o wheel google-adk 2.10.0 (release corrente) contém google.adk.skills (load_skill_from_dir, load_skills_from_dir) e google.adk.tools.skill_toolset.SkillToolset, cujo construtor aceita skills, skills_folder, code_executor, additional_tools, tool_filter, discovery_mode e lifecycle_config. O recurso segue Experimental. Desde a 2.10.0 existe um ciclo de vida de skills também experimental (ativação efêmera por turno, tool unload_skill opt-in, SkillDiscoveryMode), ligado por ADK_ENABLE_SKILL_LIFECYCLE=1 (notas de release v2.10.0; o símbolo unload_skill e a variável aparecem no código do wheel). Detalhe em guia_google_adk.html#skills.

Plugin completo — sem envelope nativo; padrão manual

O ADK não tem um terceiro objeto que amarre skill+MCP num "plugin" instalável (sentido 1 do vocabulário). Para carregar um bundle agent-plugins.org, leia o manifest com o padrão genérico da §Templates e monte um McpToolset por servidor declarado em mcp.json, mais um SkillToolset apontando para a pasta skills/ do bundle: 

from google.adk.tools.mcp_tool import McpToolset
from google.adk.tools.mcp_tool.mcp_session_manager import StdioConnectionParams, StreamableHTTPConnectionParams
from google.adk.skills import load_skill_from_dir
from google.adk.tools import skill_toolset
from mcp import StdioServerParameters

bundle = load_plugin_manifest("./my-plugin")  # ver §Templates

mcp_toolsets = []
for name, cfg in bundle["mcp_servers"].items():
    if cfg["type"] == "stdio":
        params = StdioConnectionParams(server_params=StdioServerParameters(command=cfg["command"], args=cfg.get("args", [])))
    elif cfg["type"] == "streamable-http":
        params = StreamableHTTPConnectionParams(url=cfg["url"], headers=cfg.get("headers", {}))
    else:
        continue  # "sse" é legado e suporte opcional: decida explicitamente
    mcp_toolsets.append(McpToolset(connection_params=params))

skills = [load_skill_from_dir(p) for p in pathlib_list(bundle["skills_dir"])]
skills_toolset = skill_toolset.SkillToolset(skills=skills) if skills else None

root_agent = Agent(
    model="gemini-flash-latest",
    name="plugin_user_agent",
    tools=[*mcp_toolsets, *( [skills_toolset] if skills_toolset else [] )],
)

Não é API do ADK — é a receita de vidraça entre "ler um bundle" e "as duas classes nativas do ADK".

BasePlugin — o outro "plugin" (lifecycle hooks)

Fonte: código do wheel google-adk 2.10.0, google/adk/plugins/base_plugin.py (inspecionado em 2026-09-30). A classe define, entre outros, before_run_callback, before_agent_callback, before_model_callback, after_model_callback, before_tool_callback, after_tool_callback e os callbacks de erro (on_tool_error_callback, on_model_error_callback). Os parâmetros são somente nomeados e o de argumentos de tool se chama tool_args. 

from google.adk.plugins.base_plugin import BasePlugin
from google.adk.runners import Runner

class AuditPlugin(BasePlugin):
    async def before_tool_callback(self, *, tool, tool_args, tool_context):
        print(f"chamando tool {tool.name} com {tool_args}")
    async def after_model_callback(self, *, callback_context, llm_response):
        print("resposta do modelo recebida")

runner = Runner(agent=root_agent, plugins=[AuditPlugin(name="AuditPlugin")])

6. LangGraphAtualizado · 2026-09-30

langgraph 1.2.12 (PyPI, verificado 2026-09-30; sem versão nova desde 2026-09-21). O pacote langgraph em si é um motor de grafo de estados — ele não publica um módulo langgraph.mcp, um conceito de skill nem um conceito de plugin próprios. A integração passa sempre por anexar tools do LangChain (produzidos por langchain.mcp.MCPAdapter ou, na convenção anterior, langchain-mcp-adapters, arquivado) a um node ou a um ToolNode.

MCP — via adapter, ligado a um node

from langgraph.graph import StateGraph, MessagesState, START
from langgraph.prebuilt import ToolNode, tools_condition
from langchain.mcp import MCPAdapter
from langchain.chat_models import init_chat_model

async def build_graph():
    async with MCPAdapter("https://mcp.example.com/mcp") as adapter:
        tools = await adapter.list_tools()
        model = init_chat_model("anthropic:claude-sonnet-5-5").bind_tools(tools)

        def call_model(state: MessagesState):
            return {"messages": [model.invoke(state["messages"])]}

        graph = StateGraph(MessagesState)
        graph.add_node("agent", call_model)
        graph.add_node("tools", ToolNode(tools))
        graph.add_edge(START, "agent")
        graph.add_conditional_edges("agent", tools_condition)
        graph.add_edge("tools", "agent")
        return graph.compile()

Isso é via adapter, não nativo: o node tools executa funções que o LangChain adaptou a partir do servidor MCP — o LangGraph em si não sabe o que é MCP, só executa ToolNode como executaria qualquer outro tool LangChain.

Mesma situação do LangChain puro: sem SkillsMiddleware no langgraph em si. Se o objetivo é progressive disclosure real de skills dentro de um grafo, o caminho verificado é subir para Deep Agents (§7), que já é "LangGraph por baixo + middleware de skills por cima" — não reinvente isso na mão a menos que precise de um grafo customizado que Deep Agents não cobre.

Plugin completo — sem API própria

Mesmo padrão manual das outras seções: leia o manifest do bundle, construa os tools MCP via langchain.mcp e injete-os no ToolNode; para skills, use o loader manual como contexto adicional no node que monta o prompt.

Este guia não encontrou, na doc oficial, uma seção de guia_langgraph.html dedicada a MCP — para hardening de servidor e padrões de segurança mais gerais de tool-use, ver guia_ferramentas_mcp_rag.html#mcp-como-fronteira e guia_protocolo_mcp.html#bibliotecas (SDKs oficiais por linguagem). 10. Segurança

Confiança em plugins de terceiros

Um plugin (sentido 1 ou 2) é código com três superfícies de execução: hooks rodam comandos de shell, servidores MCP stdio são subprocessos que herdam o ambiente do seu processo pai, e scripts de skill (scripts/ dentro de um SKILL.md) são executáveis arbitrários. Trate um plugin de terceiro como dependência de supply chain:

  • Fixe por commit/versão, nunca instale de uma URL não controlada — a própria doc do Claude Code é explícita quanto a --plugin-url: "only point this flag at archives you control or trust".
  • Revise hooks/hooks.json e .mcp.json/mcp.json antes de habilitar — são os dois arquivos que declaram comandos executáveis e processos externos.
  • agent-plugins.org 1.0.0 não define modelo de permissão, sandboxing nem verificação de assinatura — a doc primária deixa isso "under each client's control". Não assuma que o formato do bundle, por si, garante algo; o enforcement é 100% do seu harness.
  • O campo allowed-tools do frontmatter de SKILL.md continua Experimental (ver guia_skills.html): sua sintaxe não concede autorização nem define semântica portátil de execução — não é uma allowlist de segurança por si só.

Allowlist de servidores MCP

Checklist reconfirmado na doc oficial do ADK (adk.dev/tools-custom/mcp-tools, 2026-09-23; sem mudança conhecida na 2.10.0), aplicável em espírito a qualquer framework desta matriz:

  • Filtre tools expostos com tool_filter (ADK) / allowedTools+wildcard restrito (Claude Agent SDK) / tool_filter (OpenAI Agents SDK) — nunca exponha o servidor inteiro por padrão.
  • Valide inputs de tool MCP para evitar injeção — o cliente nunca deve confiar cegamente no schema anunciado por um servidor remoto.
  • Use caminhos de arquivo restritivos para servidores MCP de filesystem (ex.: server-filesystem recebendo um diretório específico, não a raiz).
  • Prefira tool filters read-only em produção quando o servidor suportar (ex.: header X-MCP-Readonly: true visto no exemplo oficial do GitHub MCP server para ADK).
  • Use headers de autenticação para conexões MCP remotas e restrinja acesso de rede entre o agente e o servidor MCP.

Para o modelo de ameaça de MCP como fronteira (hardening de servidor, provenance, HITL), ver guia_ferramentas_mcp_rag.html#hardening-de-mcp-server e guia_protocolo_mcp.html para auth/versão do protocolo em si.

Sandbox de scripts de skill — o modelo de confiança muda por framework

FrameworkOnde o script de skill roda
Claude Agent SDK / Claude CodeVia tool Bash, sujeito ao permission_mode/allowed_tools da sessão — sem isolamento de processo dedicado por padrão.
OpenAI Agents SDK (Sandbox Agents)Dentro do sandbox do agente (isolamento de container/VM conforme o sandbox client escolhido) — a skill é montada e executada isolada do processo host.
Google ADKComo tool Python normal dentro do processo do agente — sem sandbox dedicado nesta verificação; scripts de skill herdam os privilégios do processo ADK.
Deep AgentsVia backend (FilesystemBackend ou outro) — o isolamento depende de qual backend você escolheu, não é garantido pelo SkillsMiddleware em si.

Não trate "a skill roda em algum lugar" como constante entre frameworks — o nível de isolamento real varia, e só o caminho Sandbox Agents da OpenAI documenta isolamento de execução como parte central do desenho.

11. Armadilhas

  • ADK "plugin" ≠ bundle de plugin. Ver Vocabulário — BasePlugin é lifecycle hook, não skill+MCP empacotados.
  • Deep Agents: skills_metadata=None, não [], para recarregar. Lista vazia significa "já carreguei e não achei nada" — o agente perde a visão de todas as skills pelo resto da thread.
  • OpenAI Agents SDK: Skills só dentro de Sandbox Agents. Não existe o mesmo mecanismo de progressive disclosure para um agente comum com function tools/handoffs, e o mantenedor declarou na issue #5025 (2026-09-17) que não há plano de adicioná-lo neste SDK.
  • LangChain: MCPAdapter com string só aceita URL. Passar o nome de um arquivo .py/.js como string não funciona como você espera — use Path(...) explicitamente para lançar como subprocesso stdio.
  • Claude Agent SDK: setting_sources explícito substitui o padrão. O padrão de query() carrega user e project. Se você setar setting_sources (ex.: []) sem esses dois valores, nenhuma skill é descoberta; o mesmo vale para skills em diretórios adicionais (add_dirs), que dependem da fonte project.
  • allowed-tools no frontmatter é Experimental. Não é uma allowlist de segurança portátil entre clientes — cada harness precisa impor sua própria política.
  • Google ADK Skills: gate de versão publicado é da linha 1.x. A doc cita "v1.25.0+"; na linha 2.x o recurso está presente (confirmado no wheel 2.10.0), mas continua Experimental — fixe a versão e cubra com testes.
  • @openai/agents (JS): não assuma paridade de Skills com Python. A navegação da doc não lista uma capability equivalente; o próprio anúncio da OpenAI descreveu a atualização de sandbox como "Python-first, TypeScript planned".
  • "Plugin" do langchain-plugins não afeta seu código Python. É um marketplace para CLIs (dcode/Claude Code/Codex) — instalar um plugin ali não muda o comportamento de um create_agent(...) chamado em processo.
  • agent-plugins.org 1.0.0 não define segurança. Sem modelo de permissão, sandbox ou assinatura na spec — todo o enforcement fica com o cliente que carrega o bundle.

Templates copy-paste — padrão manual portável

As duas receitas abaixo não são API de nenhum framework — são o padrão desta coleção para os casos em que a matriz da §2 mostra Padrão manual. Adapte o glue final (como os objetos entram no framework escolhido) usando as receitas nativas das §3–8.

A — Loader manual de SKILL.md com progressive disclosure

"""Padrão manual (não é API de framework): descoberta L1 + load_skill L2/L3.
Especificação de SKILL.md: ver guia_skills.html — este loader só implementa o
contrato genérico (name/description obrigatórios), sem validar todos os campos opcionais.
"""
import glob
import os
from pathlib import Path

import yaml  # PyYAML — qualquer parser de frontmatter serve


def discover_skills(skills_dir: str) -> list[dict]:
    """L1: metadata (name + description) de cada SKILL.md encontrado — o único
    custo de contexto pago antecipadamente."""
    skills = []
    for md_path in glob.glob(os.path.join(skills_dir, "*", "SKILL.md")):
        text = Path(md_path).read_text(encoding="utf-8")
        if not text.startswith("---"):
            continue
        _, frontmatter, _ = text.split("---", 2)
        meta = yaml.safe_load(frontmatter)
        skills.append({
            "name": meta["name"],
            "description": meta["description"],
            "path": md_path,
            "dir": os.path.dirname(md_path),
        })
    return skills


def render_catalog(skills: list[dict]) -> str:
    """Texto para o system prompt — só nome + description por skill."""
    lines = ["Skills disponíveis (carregue com load_skill(name) quando for relevante):"]
    lines += [f"- {s['name']}: {s['description']}" for s in skills]
    return "\n".join(lines)


def load_skill(name: str, skills: list[dict]) -> str:
    """L2: corpo completo do SKILL.md — só quando o modelo chamar este tool."""
    match = next(s for s in skills if s["name"] == name)
    return Path(match["path"]).read_text(encoding="utf-8")

# Uso: registre `load_skill` como tool comum do seu framework (function tool,
# @tool, etc.) e injete `render_catalog(discover_skills(...))` no system prompt.
# Arquivos em references/ e assets/ (L3) só devem ser lidos se o corpo da skill
# (L2) os referenciar — não pré-carregue.

B — Loader manual de bundle de plugin (plugin.json + mcp.json + skills/)

"""Padrão manual (não é API de framework): lê um bundle no formato geral
plugin.json + mcp.json + skills/ (agent-plugins.org 1.0.0, ou o layout Claude Code
com .claude-plugin/plugin.json e .mcp.json — os formatos são distintos; ajuste ao bundle real).
Não expande ${PLUGIN_ROOT}/${PLUGIN_DATA} nem valida o schema: faça isso antes de confiar no bundle."""
import json
from pathlib import Path


def load_plugin_manifest(plugin_dir: str) -> dict:
    root = Path(plugin_dir)
    manifest_path = root / "plugin.json"
    if not manifest_path.exists():
        manifest_path = root / ".claude-plugin" / "plugin.json"  # layout Claude Code — ver §8
    manifest = json.loads(manifest_path.read_text(encoding="utf-8"))

    mcp_path = root / "mcp.json"
    if not mcp_path.exists():
        mcp_path = root / ".mcp.json"  # layout Claude Code — ver §8
    mcp_config = json.loads(mcp_path.read_text(encoding="utf-8")) if mcp_path.exists() else {}

    skills_dir = root / "skills"
    return {
        "manifest": manifest,
        "mcp_servers": mcp_config.get("mcpServers", {}),
        "skills_dir": str(skills_dir) if skills_dir.is_dir() else None,
    }

# Uso: para cada entrada em bundle["mcp_servers"], instancie a classe MCP NATIVA
# do seu framework (McpToolset/MCPServerStdio/MCPAdapter/mcp_servers dict/MCPToolset)
# com os mesmos campos (command/args/env para stdio; url/headers para http) —
# ver as receitas de MCP nas §3–8. Para bundle["skills_dir"], use o loader nativo
# de skills do framework quando existir (ADK SkillToolset, Deep Agents skills=[...],
# Claude Agent SDK setting_sources), ou o Template A quando não existir.
