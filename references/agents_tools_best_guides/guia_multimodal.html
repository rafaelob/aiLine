Resumo para agentes (verificado 2026-10-24) ¶

Use este guia quando

  • precisar escolher provider e modelo para entrada de imagem, PDF, planilha, vídeo ou áudio (e para geração de imagem, vídeo e voz);
  • precisar dos limites e formatos de arquivo por provider antes de montar o request;
  • precisar da forma exata do bloco de mídia na Responses (OpenAI), na Interactions (Gemini) ou na Messages (Anthropic).

Não é aqui

  • Contar tokens e custo real da chamada: guia_token_counting.html.
  • Enviar arquivo sem storage do provider (modo A, ZDR) e execução hospedada (modo B): guia_file_inputs_no_storage.html.
  • Code Interpreter, Code Execution, Shell, computer/browser use e tool search: guia_agentic_vision_code_tools.html.
  • Detalhe da Interactions API do Gemini: guia_gemini_interactions_api.html.

Padrões vigentes

  • OpenAI: Responses API com input_text, input_image e input_file. Entrada nativa de vídeo não é documentada: extraia quadros e envie como imagem.
  • Gemini: google-genai com Interactions (steps[]); mídia em blocos {type, data|uri, mime_type}; resolution é por item. Não envie temperature, top_p nem top_k (ignorados hoje; HTTP 400 em gerações futuras).
  • Anthropic: Messages API com blocos image e document; sem áudio nem vídeo nativos documentados. Planilhas e DOCX: Files API + code execution, ou converta para texto.
  • Arquivo grande ou reutilizado: Files API do provider; arquivo pequeno e de uso único: inline (Gemini: fique abaixo de 20 MB; as páginas oficiais divergem sobre 20 e 100 MB).
  • Tokens de mídia variam entre páginas oficiais do Gemini: meça com models.count_tokens e, na OpenAI, com responses.input_tokens.count.
  • Planilha com agregações, joins ou > 1.000 linhas (OpenAI): use code execution do provider, ou calcule no seu backend e envie só o resumo.
  • Transcrição OpenAI: gpt-transcribe (sem timestamps nem diarização). Para timestamps ou falantes use Gemini gemini-3.5-transcribe.

3.3 Imagem / visão ¶

Os três providers aceitam vision input nativamente, mas divergem em MIME types aceitos, quantidade de imagens por request, tamanho máximo por arquivo, como tokenizam o pixel e como expõem coordenadas espaciais. A tabela abaixo lado-a-lado é a referência de bolso — cada célula expande no deep-dive correspondente. Observe que a OpenAI usa patches de 32 px (multiplicador 1,2× no gpt-6-astra), o Gemini tokeniza por resolution (1.120 tokens por imagem em high segundo a página media-resolution; as páginas de image understanding e tokens dizem 258 por tile — divergência oficial) e a Anthropic usa ceil(W/28) · ceil(H/28).

3.5 Office, Excel, CSV e documentos estruturados ¶

Nenhum dos três providers tem vision nativo para formatos Office binários (DOCX/PPTX/XLSX). A estratégia universal é (a) converter para PDF quando fidelidade visual importa, (b) mandar como texto inline para CSV/TXT/MD pequenos, ou (c) delegar para o sandbox Python (Code Interpreter / Code Execution) para tabular analytics. 3.11.1 Isso é ZDR?

"API não treina por padrão" e "Zero Data Retention" são coisas diferentes; cada provider tem regras próprias de elegibilidade por endpoint e feature.

  • Áudio delimitado: STT (gpt-transcribe) → Responses. Voz de saída e voz ao vivo: Realtime em gpt-realtime-2.1 (ou -mini por custo) ou GPT-Live.
  • Imagem: gpt-image-2.5-flare (cotidiano, mais rápido) ou gpt-image-2.5-sunburst (precisão de edição), pela tool image_generation da Responses ou pela Images API.

4.2 Imagem / visão ¶

Formatos: PNG, JPEG, WEBP e GIF não animado. Até 512 MB de payload total e 1.500 imagens por request; imagens acima do orçamento do modelo são redimensionadas antes da tokenização. Três modos de entrada na Responses: input_image.image_url com URL HTTPS, input_image.image_url com data URL base64, ou input_image.file_id (Files API, purpose="vision").

image_part = {"type": "input_image", "image_url": "https://example.com/image.jpg"}      # modo 1: URL
# image_part = {"type": "input_image", "image_url": f"data:image/jpeg;base64,{b64}", "detail": "high"}  # modo 2: base64
# image_part = {"type": "input_image", "file_id": uploaded.id}                          # modo 3: Files API

detail parameter — semantics per model family

detail controls the resolution at which the model processes the image. Allowed values: low, high, original (newer models), auto (default).

DetailBehavior
lowModel receives a low-resolution 512×512 version. Fast and cheap; lose fine detail.
highHigh-fidelity tokenization (still bounded by the model's patch budget or tile budget).
originalLargest patch budget; recommended for computer-use, click-accuracy, dense text, and spatially sensitive tasks.
autoDefault. auto equals original on gpt-6-astra.

Fonte: guides/images-vision. Para OCR, detecção de objetos pequenos e computer use, a doc recomenda "detail": "original".

Model sizing behavior

Model family Supported detail levels Sizing behavior
gpt-6-astra low, high, original, auto low cabe em 512×512. high → até 2.500 patches E 65.535 px de dimensão máxima (ambos valem). original preserva as dimensões (reduz só acima de 65.535 px). auto ≡ original.
Teto de 30.000 patches por imagem. Em qualquer nível de detail, uma imagem que ainda precise de mais de 30.000 patches depois do redimensionamento é rejeitada, não reduzida. gpt-6-sol, gpt-6-luna e gpt-6.1-sol não constam na tabela de sizing oficial — UNVERIFIED se seguem as regras do Astra; confira com responses.input_tokens.count (§4.11). Fonte: guides/images-vision#model-sizing-behavior.

Token cost formulas

Os modelos atuais usam tokenização por patches de 32 × 32 px:

A. patch_count = ceil(width/32) * ceil(height/32)       (após o limite de pixels do detail)
B. se houver orçamento de patches e patch_count > orçamento, reduza a imagem proporcionalmente:
   shrink_factor = sqrt((32^2 * patch_budget) / (width * height))   (ajustado para pixels inteiros)
C. resized_patch_count = ceil(resized_width/32) * ceil(resized_height/32)
   > 30.000 → a API rejeita a request
D. billed_tokens = ceil(resized_patch_count * model_multiplier)

O multiplicador é 1,2 em gpt-6-astra (os demais modelos GPT-6: UNVERIFIED); aplica-se uma vez, só aos tokens da imagem. Exemplo oficial (gpt-6-astra, detail: high): 1024 × 1024 → 1024 patches → ceil(1024 × 1,2) = 1.229 tokens; 2048 × 2048 → reduzida a 1600 × 1600 (2.500 patches) → 3.000 tokens. Use a calculadora oficial para estimar uma imagem.

Geração e edição de imagem — gpt-image-2.5

gpt-image-2.5-sunburst (precisão de edição) e gpt-image-2.5-flare (geração cotidiana, mais rápida) são os modelos atuais (lançados em 2026-09-08). Dois caminhos: a Images API (model direto) ou a tool image_generation da Responses API, onde o modelo principal fica no topo e o de imagem vai dentro da tool.

import base64
from openai import OpenAI

client = OpenAI()

# 1) Images API
result = client.images.generate(
    model="gpt-image-2.5-flare",
    prompt="A children's book drawing of a veterinarian listening to a baby otter's heartbeat.",
    size="1024x1024",
    quality="high",
)
open("otter.png", "wb").write(base64.b64decode(result.data[0].b64_json))

# 2) Responses API (tool): o modelo principal decide quando gerar
response = client.responses.create(
    model="gpt-6-astra",
    input="Generate an image of a gray tabby cat hugging an otter with an orange scarf",
    tools=[{"type": "image_generation", "model": "gpt-image-2.5-flare"}],
)
images = [o.result for o in response.output if o.type == "image_generation_call"]
if images:
    open("cat.png", "wb").write(base64.b64decode(images[0]))
  • quality: low, medium, high, xhigh, max ou auto (padrão). size: 1024x1024, 1536x1024, 1024x1536 ou WIDTHxHEIGHT (múltiplos de 16, proporção entre 1:3 e 3:1, lado ≤ 3840 px, 655.360 a 8.294.400 pixels; acima de 2560x1440 é experimental). Formatos png (padrão), jpeg, webp; background: "transparent" exige png ou webp.
  • Tarifa por token: US$ 8 input de imagem / US$ 2 cached / US$ 30 output, por 1M; texto US$ 5 input.

Fontes: guides/image-generation · pricing.

Limitações documentadas de visão

Não serve para imagens médicas (CT, MRI) nem aconselhamento médico; pior em escritas não latinas, texto pequeno, imagens rotacionadas, gráficos que variam cor e estilo de linha, localização espacial precisa, panorâmicas e fisheye; contagens são aproximadas; CAPTCHAs são bloqueados; nomes de arquivo e EXIF não são lidos. Cada imagem conta para o limite de TPM.

4.3 PDF e documentos ¶

PDF é o único tipo de arquivo para o qual a API extrai texto e imagens de página para o contexto — apenas em modelos com visão (toda a família GPT-6). developers.openai.com/api/docs/guides/file-inputs.

Três modos de entrada em input_file: file_id (upload com purpose="user_data"), file_url ou file_data base64 com filename.

detail em input_file (PDF)

O campo opcional detail (auto por padrão, low ou high) controla as imagens de página; o texto extraído sempre entra. Use low para gastar menos tokens e high para gráficos densos, letra miúda ou diagramas. Na família gpt-6, auto usa high. Fonte: guides/file-inputs#pdf-detail-levels.

{ "type": "input_file", "file_id": "file-abc123", "detail": "high" }

Limites e tokens

  • Por arquivo: < 50 MB; o total de todos os arquivos de uma request também é limitado a 50 MB. Sem teto de páginas documentado.
  • Acima disso, ou para PDFs de centenas de páginas, use File Search (vector store) em vez de input_file.
  • Cada página contribui com dois fluxos de tokens: o texto extraído e a imagem da página (regras de imagem do modelo). count_tokens aceita file_id, file_url ou file_data e reflete a entrada processada completa.

Exemplo — os três modos

from openai import OpenAI

client = OpenAI()

uploaded = client.files.create(file=open("doc.pdf", "rb"), purpose="user_data")
b64 = base64.b64encode(open("doc.pdf", "rb").read()).decode("utf-8")

pdf_part = {"type": "input_file", "file_id": uploaded.id}                  # recomendado para reuso
# pdf_part = {"type": "input_file", "file_url": "https://example.com/doc.pdf"}
# pdf_part = {"type": "input_file", "filename": "doc.pdf", "file_data": f"data:application/pdf;base64,{b64}"}

response = client.responses.create(
    model="gpt-6-astra",

Formatos além de PDF: documentos (.docx, .rtf, .odt) e apresentações têm só o texto extraído, sem imagens nem gráficos (converta para PDF se importam); planilhas e CSV passam por spreadsheet augmentation (primeiras 1.000 linhas por aba mais metadados de cabeçalho e resumo); texto e código entram como texto puro. Comparativo: §3.5.

4.4 Planilhas ¶

Para "ache a linha em que..." ou "resuma a planilha" com até 1.000 linhas, basta input_file com o file_id do .xlsx, como no PDF. Para agregações, joins, gráficos, regressões ou mais de 1.000 linhas, use a tool code_interpreter; arquivos anexados à request são enviados ao container automaticamente.

from openai import OpenAI
client = OpenAI()

uploaded = client.files.create(
    file=open("sales_2025.xlsx", "rb"),
    purpose="user_data",
)

response = client.responses.create(
    model="gpt-6-astra",
    tools=[{
        "type": "code_interpreter",
        "container": {"type": "auto", "memory_limit": "4g", "file_ids": [uploaded.id]},
    }],
    input=[{
        "role": "user",
        "content": [
            {"type": "input_text",
             "text": "Compute total revenue by month, plot it as a line chart, and save it as revenue.png. Return the chart and a CSV of the data."},
        ],
    }],
)

for item in response.output:
    if item.type == "message":
        for part in item.content:
            if getattr(part, "type", None) == "output_text":
                print(part.text)
            for ann in getattr(part, "annotations", []) or []:
                if ann.type == "container_file_citation":
                    print("File:", ann.filename, "container:", ann.container_id, "file:", ann.file_id)

Não há vision para XLSX renderizado: para cores de célula, regiões mescladas ou capturas embutidas, exporte cada aba para PDF. O Hosted Shell é a alternativa documentada ao Code Interpreter para análise pesada de planilhas.

4.5 Code Interpreter ¶

The Code Interpreter tool runs Python in a sandboxed container that the model controls. It is exposed in the Responses API.

"While we call this tool Code Interpreter, the model knows it as the 'python tool'." — Code Interpreter guide.

Tool definition

{
  "type": "code_interpreter",
  "container": { "type": "auto", "memory_limit": "4g" }
}

container may be:

  • {"type": "auto", "memory_limit": "...", "file_ids": ["..."]} — auto-create or reuse a recent container, optionally pre-attached files.
  • "cntr_..." — an explicit container ID created via POST /v1/containers.

memory_limit accepts "1g" (default), "4g", "16g", or "64g". Higher tiers are billed at the built-in-tools rate; the limit is fixed for the container's lifetime.

Container lifecycle

  • Expiration: A container expires if it is not used for 20 minutes. Any container operation (retrieve, add file, delete file) refreshes last_active_at.
  • Recovery: You cannot reanimate an expired container — files and in-memory Python state are gone. Always treat containers as ephemeral and download any files you care about while the container is alive.
  • Discovery: Auto-created containers are still reachable via GET /v1/containers/{id}.

Arquivos aceitos no container (lista completa de MIME no guia oficial de Code Interpreter): código-fonte (.c, .cpp, .cs, .java, .js, .ts, .py, .rb, .php, .sh, .tex), texto e dados (.txt, .md, .csv, .json, .xml, .html, .css, .pkl), documentos (.pdf, .doc, .docx, .pptx, .xlsx), imagens (.jpeg, .png, .gif) e arquivos compactados (.tar, .zip).

Output retrieval — container_file_citation

When Code Interpreter writes a file, it shows up as an annotation on the assistant's message:

{
  "annotations": [{
    "type": "container_file_citation",
    "container_id": "cntr_...",
    "file_id": "cfile_...",
    "filename": "cfile_....png"
  }],
  "text": "Here is the histogram...",
  "type": "output_text"
}

Download with GET /v1/containers/{container_id}/files/{file_id}/content. List with GET /v1/containers/{container_id}/files. Add new files with POST /v1/containers/{container_id}/files (multipart or JSON with file_id).

Exemplo — container explícito e download de arquivo gerado

from openai import OpenAI
client = OpenAI()

container = client.containers.create(name="analytics", memory_limit="16g")   # ou {"type": "auto", "memory_limit": "4g"} inline

response = client.responses.create(
    model="gpt-6-astra",
    tools=[{"type": "code_interpreter", "container": container.id}],
    tool_choice="required",
    input="use the python tool to plot y = x**2 and save it as plot.png",
)

# annotation.container_id e annotation.file_id vêm de container_file_citation na resposta
for item in response.output:
    for part in getattr(item, "content", None) or []:
        for ann in getattr(part, "annotations", None) or []:
            if ann.type == "container_file_citation":
                binary = client.containers.files.content.retrieve(
                    file_id=ann.file_id, container_id=ann.container_id)
                open(ann.filename, "wb").write(binary.read())

Limits and pricing

  • API availability: Responses.
  • Rate limit: 100 RPM per org for Code Interpreter calls.
  • Pricing: billed at the built-in-tools rate; higher memory_limit tiers cost more (1g < 4g < 16g < 64g). Eligible container sessions are billed per minute with a 5-minute minimum (OpenAI changelog).
  • ZDR: ver §3.11.1 (armazenamento efêmero do container).

4.6 Vídeo ¶

A OpenAI não gera vídeo e a Responses API não tem entrada nativa de vídeo (não existe input_video). O padrão suportado é extração de frames + transcrição do áudio: divida o vídeo em N quadros, envie-os como input_image[] e transcreva a faixa de áudio com gpt-transcribe (§4.7). Para vídeo nativo ou geração use o Gemini (Gemini Omni).

Frame-extraction workflow (the working pattern)

import base64
import cv2
from openai import OpenAI

client = OpenAI()

def extract_frames(video_path, every_n_seconds=2, max_frames=24):
    cap = cv2.VideoCapture(video_path)
    step = int(cap.get(cv2.CAP_PROP_FPS) * every_n_seconds)
    frames, idx = [], 0
    while cap.isOpened() and len(frames) < max_frames:
        ok, frame = cap.read()
        if not ok:
            break
        if idx % step == 0:
            frames.append(base64.b64encode(cv2.imencode(".jpg", frame)[1].tobytes()).decode("utf-8"))
        idx += 1
    cap.release()
    return frames

# Transcrição da faixa de áudio (extraia o áudio antes, p. ex. com ffmpeg; limite de 25 MB)
with open("meeting.mp3", "rb") as audio:
    transcript = client.audio.transcriptions.create(model="gpt-transcribe", file=audio).text

frames = extract_frames("meeting.mp4", every_n_seconds=2, max_frames=24)
content = [{"type": "input_text", "text": "Summarize this meeting clip. Audio transcript:\n" + transcript}]
content += [
    {
        "type": "input_image",
        "image_url": f"data:image/jpeg;base64,{f}",
        "detail": "low",
    }
    for f in frames
]

resp = client.responses.create(
    model="gpt-6-astra",
    input=[{"role": "user", "content": content}],
)
print(resp.output_text)

Transcrição de arquivo — gpt-transcribe

gpt-transcribe é o modelo recomendado para gravações no idioma original. Aceita prompt (contexto livre), keywords (termos literais esperados) e languages (idiomas de entrada esperados), que substitui o language singular — não envie os dois. Cada keyword fica em uma linha, sem <, >, CR ou LF; a API rejeita a request inteira se encontrar esses caracteres ou se o prompt passar do limite. A resposta traz text e languages detectados ([] quando não há previsão confiável). Keywords são dicas, não saída obrigatória.

from openai import OpenAI
client = OpenAI()

with open("meeting.wav", "rb") as audio_file:
    transcription = client.audio.transcriptions.create(
        model="gpt-transcribe",
        file=audio_file,
        prompt="A customer support call about a premium plan and account AC-42.",
        extra_body={
            "keywords": ["premium plan", "AC-42", "billing"],
            "languages": ["en", "fr"],
        },
    )

print(transcription.text)

Formato do extra_body conforme o guia oficial: keywords e languages não aparecem como parâmetros tipados nos exemplos de Python e JS (em TypeScript vão no body da request). Códigos de idioma aceitos: ISO 639-1 (en, fr), ISO 639-3 selecionados (eng, yue, cmn) e locales zh-cn/zh-tw/zh-hk; códigos inválidos são rejeitados.

Streaming

  • Arquivo já gravado: stream=True com gpt-transcribe emite eventos transcript.text.delta e fecha com transcript.text.done (que inclui languages). Não exige sessão Realtime.
  • Áudio ao vivo: sessão Realtime com type: "transcription" e gpt-live-transcribe (WebSocket para pipelines de servidor, WebRTC para áudio de navegador); PCM 24 kHz; omita audio.input.turn_detection ou use null — o modelo não suporta server_vad nem semantic_vad. Aceita prompt, keywords e languages; não devolve timestamps por palavra, rótulos de falante, confiança nem idioma detectado.
Timestamps, legendas (srt/vtt), diarização e tradução para inglês não existem no gpt-transcribe e a OpenAI não nomeia um modelo atual para essas funções; use gemini-3.5-transcribe (§3.7).

Áudio acima de 25 MB: use formato comprimido ou divida em pedaços sem cortar frases e carregue o contexto do pedaço anterior pelo prompt.

Realtime audio

  • Conecte por WebSocket ou WebRTC (gpt-realtime-2.1, gpt-realtime-translate, gpt-realtime-whisper); o GPT-Live (gpt-live-1) usa /v1/live/sessions.
  • Envie PCM16 com input_audio_buffer.append (cada chunk ≤ 15 MB) e use VAD do servidor (session.update) ou faça commit manual; receba response.output_audio.delta (PCM base64). Sem MP3 ou Opus.
  • Duração máxima de uma sessão Realtime: 60 minutos (realtime-conversations).

Saída de voz

A saída de voz da OpenAI passa pela família gpt-realtime-* (gpt-realtime-2.1-mini por custo); o /v1/audio/speech não é suportado por ela.

4.8 Files API ¶

Endpoints: POST /v1/files (file, purpose, expires_after opcional), GET /v1/files (filtros purpose, limit, after, order), GET /v1/files/{file_id}, DELETE /v1/files/{file_id} e GET /v1/files/{file_id}/content (bytes brutos).

purpose: user_data para arquivos que serão entrada de modelo (input_file), vision para imagens por file_id, batch para o JSONL da Batch API (até 200 MB), fine-tune e evals.

Limites e expiração

  • Por arquivo: 512 MB. Por projeto: 2,5 TB (sem limite por organização). Uploads: 1.000 requests/min por usuário.
  • input_file: cada arquivo < 50 MB e no máximo 50 MB combinados por request.
  • Vector stores criadas a partir de novembro/2025 anexam até 100.000.000 arquivos (2.000 anexos/min por organização). Arquivos de saída do Batch ficam 30 dias.
  • Os arquivos persistem até serem apagados; expires_after (anchor=created_at mais seconds) define auto-deleção. Arquivos de container expiram com ele (20 min idle).
from openai import OpenAI
client = OpenAI()

uploaded = client.files.create(file=open("manual.pdf", "rb"), purpose="user_data")
for f in client.files.list(purpose="user_data", limit=10).data:
    print(f.id, f.filename)

client.files.delete(uploaded.id)

4.10 Limitações & gotchas ¶

Cross-cutting list to surface as "watch outs" in the comparative HTML guide.

Vision

  • Medical images: not for diagnosis.
  • Non-Latin scripts and small text are weaker — enlarge text, prefer detail: "original".
  • Images needing more than 30,000 patches are rejected, not resized.
  • Rotated content can be misread.
  • Graphs with dashed/dotted/colored variants: weak comprehension.
  • Spatial reasoning (chess, layout) is unreliable.
  • Panoramas and fisheye distortion: weak.
  • File metadata (EXIF, filename) is never read.
  • CAPTCHAs are blocked.
  • TPM accounting: every image counts.
  • Counting objects: approximate.

Files

  • input_file is per-request capped at 50 MB total (per file ≤ 50 MB).
  • Non-PDF docs lose embedded images/charts (text-only extraction). Convert to PDF if visuals matter.
  • Spreadsheet ingestion stops at the first 1,000 rows per sheet. Use Code Interpreter or Hosted Shell for larger sheets.
  • PDF parsing needs vision-capable models (família gpt-6).
  • purpose matters: model-input use cases should use user_data.

Code Interpreter

  • Container expires after 20 minutes of idle.
  • All container files vanish at expiration — download what you need.
  • Filesystem is ephemeral block storage; no networking unless explicitly enabled.
  • memory_limit is fixed for life of container.
  • Rate limit: 100 RPM per org for the tool.

Audio

  • Transcription upload: 25 MB max, must be chunked for longer.
  • gpt-transcribe: no timestamps, no diarization, no subtitle formats, no translation; language (singular) is replaced by languages[].
  • gpt-live-transcribe: no word timestamps, speaker labels, confidence or detected language; no server_vad/semantic_vad.
  • Realtime sessions: 60-minute max; chunks ≤ 15 MB; PCM16/G.711 only; no MP3/Opus input.

Video

  • No native video input on Responses; use the frame-extraction + transcription pattern.
  • No video generation on OpenAI.

Gemini Interactions API — deep dive ¶

A Interactions API é a superfície padrão deste guia para Gemini 3.x. Mantém estado server-side via previous_interaction_id, devolve uma timeline tipada de steps[] (em vez de candidates[].content.parts[]), roda tarefas longas em background (background=true), permite cancelamento explícito e retomada de SSE por last_event_id, e recebe a entrada em input[] com itens tipados (text, image, audio, video, document). Esta seção cobre cada modalidade, tool, parâmetro, tipo de step, limite e gotcha, com exemplos em Python e curl. Contratos conforme a overview oficial e as páginas por modalidade (imagem, documentos, vídeo, áudio, transcrição, fala, function calling).

Status: GA e recomendada para projetos novos desde junho/2026. steps[] é o único schema de resposta. Os três recursos que ainda só existem no generateContent estão em §5.2. A overview cobre o Gemini Developer API.

6.1 API surface ¶

6.2 Imagem / visão ¶

Imagens entram como itens do array input[] com type: "image": um único objeto com discriminador type e os bytes em data (base64) ou a referência em uri. Coloque o prompt de texto antes da imagem no array. Tokenização oficial (página de image understanding): 258 tokens se os dois lados têm até 384 px; acima disso a imagem é dividida em tiles de 768×768 px de 258 tokens cada.

MIME aceitos (página oficial de image understanding): image/png, image/jpeg, image/webp, image/heic, image/heif. GIF, BMP e TIFF não constam: converta para PNG/JPEG. Caminhos de envio: data inline, uri da Files API (files/...), gs:// ou URL HTTPS pública que devolva MIME válido.

Limites

  • 3.600 imagens por request (combinado com texto e outras modalidades).
  • Inline: a página de métodos de entrada (file-input-methods) fixa 100 MB por request (PDF: 50 MB); as páginas de imagem e de áudio ainda dizem 20 MB totais. Divergência oficial não reconciliada — acima de ~20 MB prefira a Files API.
  • Tokens por imagem: a página de image understanding e a de tokens dizem 258 tokens por tile (≤ 384 px = 258); a página media-resolution dá, para Gemini 3, low 280 · medium 560 · high 1.120 · ultra_high 2.240, com default 1.120. As duas tabelas não são reconciliadas pela documentação: para custo real leia interaction.usage; para estimar antes, use client.models.count_tokens.
  • resolution por item (somente Gemini 3) troca custo por acurácia: low/medium baratos; high é o recomendado para análise de imagem e ultra_high para Computer Use e OCR fino.

6.4 Office / Excel / CSV ¶

A Interactions API não tem conversores nativos para .docx, .pptx, .xlsx, .csv. Há dois caminhos práticos:

  1. Pré-converter para PDF (LibreOffice headless, Aspose, scripts) e enviar como {type:"document", mime_type:"application/pdf"} — preserva layout, gráficos e tabelas com fidelidade visual.
  2. Usar a tool code_execution (ver §6.5) e deixar o sandbox Python ler o arquivo com openpyxl, pandas, python-docx, python-pptx. Útil para analytics e transformação tabular.

A página oficial de documentos afirma que só PDF é entendido visualmente; TXT, Markdown, HTML, XML e similares são extraídos como texto puro (tags, formatação e gráficos se perdem). .docx, .pptx e .xlsx não são citados como entrada nativa: siga os dois caminhos acima.

        {"type": "text", "text": "Qual o ticket médio por mês no CSV? Retorne uma tabela markdown."},

6.6 Vídeo ¶

Vídeos entram como {type: "video"}. O campo processing do item escolhe como o vídeo vai ao contexto: "static" (default em todos os modelos: frames a 1 FPS, áudio a 1 Kbps mono, timestamps por segundo) ou "agentic" (o modelo navega pela linha do tempo e carrega só a transcrição, os frames e o áudio de que precisa; a doc cita até 88% menos tokens e ~7% mais qualidade em vídeo longo). O modo agentic está disponível em Gemini 3.8 Flash e 3.5 Flash-Lite. Comece por agentic em vídeos longos ou perguntas sobre momentos específicos; use static em clipes < 5 min sensíveis a latência ou quando precisar de precisão por frame. Recorte (start_offset/end_offset) e FPS customizado só existem em static. resolution (tokens por frame) e processing são independentes e combináveis.

MIME aceitos: video/mp4, video/mpeg, video/mov, video/avi, video/x-flv, video/mpg, video/webm, video/wmv, video/3gpp.

6.7 Áudio ¶

Áudio entra como {type: "audio"}. Internamente o Gemini reamostra para 16 Kbps e combina canais em mono; a página de áudio cobra 32 tokens/segundo (1 minuto = 1.920 tokens; 1 hora ≈ 115.200) e entende também sons que não são fala. A página media-resolution dá 25 tokens/s para Gemini 3 — divergência oficial não reconciliada; use usage para custo real.

MIME aceitos: audio/wav, audio/mp3, audio/mpeg, audio/aiff, audio/aac, audio/ogg, audio/flac, audio/m4a, audio/opus, audio/alaw, audio/mulaw, audio/l16, audio/webm.

Limites

  • 9,5 horas por prompt (página de áudio).
  • Inline: a página de áudio diz 20 MB de request total; a tabela de métodos de entrada diz 100 MB (divergência oficial). Acima de ~20 MB use a Files API.
  • Sem transcrição em tempo real via interactions.create: use a Live API (gemini-3.8-live).

Exemplo Python — entender o áudio (resumo, perguntas)

audio = client.files.upload(file="reuniao.wav")

interaction = client.interactions.create(
    model="gemini-3.8-flash",
    input=[
        {"type": "text", "text": "Resuma a reunião em 3 bullets e liste as decisões."},
        {"type": "audio", "uri": audio.uri, "mime_type": audio.mime_type},
    ],
)
print(interaction.output_text)

Transcrição (STT) com gemini-3.5-transcribe

Para transcrição use o modelo dedicado gemini-3.5-transcribe (GA 2026-08-26): detecção automática de idioma (85+ locales, com code-switching), diarização, timestamps por palavra e vocabulário customizado. O comportamento fica em generation_config.transcription_config; o modo default é verbatim.

interaction = client.interactions.create(
    model="gemini-3.5-transcribe",
    input=[{"type": "audio", "uri": audio.uri, "mime_type": audio.mime_type}],
    generation_config={
        "transcription_config": {
            "language_codes": ["pt-BR"],          # opcional; vazio = detecção automática
            "mode": {
                "type": "verbatim",
                "diarization_mode": "speaker",     # spk_1, spk_2 ... (até 8 falantes)
                "timestamp_granularities": ["word"],
            },
        }
    },
)
print(interaction.output_text)
  • "mode": "smart" remove disfluências e formata o texto (parágrafos, listas, datas, valores), mas não combina com diarização nem com timestamps.
  • custom_vocabulary (até 1.000 termos; melhor com até 100) não combina com diarização nem com timestamps — a API rejeita a request.
  • Limites: 1 hora de áudio por request unária; 30 minutos quando diarização ou timestamps por palavra estão ligados. Timestamps por palavra podem reduzir a acurácia. Preço: US$ 0,003/min de áudio de entrada.

Fonte: transcribe e pricing.

Geração de áudio (TTS)

Os modelos gemini-3.8-flash-tts (GA 2026-09-22) e gemini-3.8-flash-lite-tts tratam o texto de entrada como transcrição literal: instruções de entrega (estilo, ritmo) e rótulos de falante vão em anotações speech_metadata, e eventos vocais pontuais ficam inline entre ângulos (<laugh>, <short pause>). O formato de saída vai em response_format={"type": "audio"} e voz/falantes em generation_config.speech_config.

import base64

interaction = client.interactions.create(
    model="gemini-3.8-flash-tts",
    input=[{
        "type": "user_input",
        "content": [{
            "type": "text",
            "text": "Boas-vindas ao nosso serviço!",
            "annotations": [{"type": "speech_metadata", "style": "cheerful and friendly"}],
        }],
    }],
    response_format={"type": "audio"},
    generation_config={"speech_config": [{"voice": "Kore"}]},
)
with open("saida.wav", "wb") as f:
    f.write(base64.b64decode(interaction.output_audio.data))
  • Multi-speaker: speech_config = {"mode": "conversational", "speakers": [{"speaker": "Joe", "voice": "Puck"}, {"speaker": "Jane", "voice": "Kore"}]}, com cada turno como um item de texto com speech_metadata.speaker.
  • Formato: resposta unária = WAV (audio/wav, 24 kHz mono 16-bit); em streaming, PCM bruto audio/l16. Em response_format também aceita audio/mulaw, audio/alaw e sample_rate (ex.: 24000, 16000, 8000).
  • Vozes: pré-construídas, biblioteca estendida (GET /v1beta/voices), voice design e voice replication (IDs voice_…).

Fonte: speech-generation.

6.9 Cache implícito ¶

Na Interactions API o caching é implícito: habilitado automaticamente e best-effort, tanto no modo stateful (com previous_interaction_id) quanto no stateless. O mínimo é de 4.096 tokens de prefixo idêntico no Gemini 3.8 Flash e no gemini-4-argon (no Argon, em multi-turn só se cacheia o request anterior inteiro se ≥ 2.050 tokens foram adicionados; o gemini-3.5-flash-lite não consta na página de caching). Em hits, os tokens cacheados aparecem em usage.total_cached_tokens e usage.cached_tokens_by_modality; ausência de hit é comportamento possível, não falha de contrato. O cache explícito (client.caches) não existe na Interactions: use o exemplo de §5.2 (o Argon não tem cache explícito). Fonte: caching.

Exemplo Python — cache implícito via multi-turn

i1 = client.interactions.create(
    model="gemini-3.8-flash",
    input=[
        {"type": "text", "text": "Leia este edital."},
        {"type": "document", "uri": edital.uri, "mime_type": "application/pdf"},
    ],
)
print(i1.usage.total_input_tokens, i1.usage.total_cached_tokens)
# segundo turno: prefixo idêntico cacheado server-side
i2 = client.interactions.create(
    model="gemini-3.8-flash",
    previous_interaction_id=i1.id,
    input="Qual o objeto da licitação?",
)
print(i2.usage.total_cached_tokens)   # > 0 indica hit

Forking de conversas

Aponte previous_interaction_id para qualquer interaction.id anterior — não precisa ser o último turno. Isso permite ramificar a árvore de conversas sem perder o prefixo cacheado, útil para multi-tenant ou A/B em ramos diferentes.

6.13 Limitações & gotchas ¶

O que não está na Interactions API

  • Batch API, cache explícito (client.caches) e Automatic Function Calling (Python): continuam no generateContent — ver §5.2. A Interactions aceita safety_settings na criação da interação.
  • Live API é superfície independente (WebSocket); Interactions é request/response com SSE.
  • Contagem de tokens: estime antes com client.models.count_tokens(...) (SDK > 2.0.0); o uso real vem em interaction.usage (em streaming, só no interaction.completed).

Limites quantitativos

  • Inline: 100 MB por request (PDF 50 MB) na página de métodos de entrada; as páginas de imagem, áudio e vídeo ainda citam 20 MB — divergência oficial não reconciliada.
  • Imagens: 3.600 por request. Áudio: 9,5 horas por prompt. PDF: 50 MB ou 1.000 páginas.
  • Vídeo: Files API até 20 GB (pago) / 2 GB (free); ~3 h em resolução baixa ou ~1 h em alta no contexto de 1M. STT dedicado: 1 h por request (30 min com diarização ou timestamps por palavra).
  • Files API: retenção 48h; 2 GB por arquivo, 20 GB por projeto.
  • Retenção de interaction.id: 55 dias (pago) / 1 dia (free).
  • Tokens por mídia: as páginas de imagem/áudio/vídeo/tokens (258 por tile, 32 tokens/s) divergem da página media-resolution (1.120 por imagem, 25 tokens/s, 70 por frame): confie em usage.

Edge cases e gotchas

  • store=false bloqueia previous_interaction_id e background=true — combinação impossível.
  • tools, system_instruction e generation_config são por interação: reenvie a cada turno, inclusive ao devolver function_result.
  • Em streaming, o interaction.completed traz usage mas não traz steps; reconstrua pelos deltas ou faça GET /interactions/{id}. Argumentos de function_call chegam em delta.partial_arguments (delta.type == "arguments"): acumule antes do json.loads().
  • thought_signature é opaco — não parseie. Em modo stateless devolva os steps de pensamento e de processing_* intactos.
  • Thinking: no gemini-3.8-flash minimal retorna erro; não defina temperature/top_p/top_k.
  • MCP remoto em Gemini 3: a overview diz não suportado ("coming soon") e a página de function calling documenta mcp_server — UNVERIFIED; teste antes de usar.
  • ZDR e retenção (store=false, cache implícito, Files API): §3.11.1.
Anthropic Claude

Anthropic — deep dive ¶

Anthropic Claude trata multimodalidade de forma deliberadamente enxuta: visão (JPEG/PNG/GIF/WebP) e PDF são nativos no endpoint POST /v1/messages; CSV/XLSX/DOCX/PPTX entram pelo Code Execution tool (sandbox Python 3.11); áudio e vídeo não têm bloco de conteúdo nativo — o caminho oficial é pré-processar (transcrição, extração de frames) e mandar o resultado como blocos text/image. Limitações de visão

  • Identificação de pessoas: Claude não nomeia pessoas em imagens e recusa fazê-lo (Acceptable Use Policy).
  • Precisão: alucinações/erros em imagens de baixa qualidade, rotacionadas ou abaixo de 200 px.
  • Raciocínio espacial limitado: relógios, posições de peças de xadrez, layouts finos.
  • Contagem: aproximada para grandes quantidades de objetos pequenos.
  • Detecção de imagem gerada por IA: Claude não detecta de forma confiável imagens sintéticas — não use como detector de fake.
  • Conteúdo impróprio é recusado por AUP.
  • Saúde: pode analisar imagens médicas gerais, mas não é ferramenta de diagnóstico para CT/MRI; jamais substitua aconselhamento médico.
  • Metadados: Claude não lê EXIF nem metadados de imagem.
  • Persistência: uploads via base64/URL são efêmeros, descartados após a request; imagens via Files API persistem até serem deletadas.
  • Geração/edição: Claude é image-understanding only. Não gera nem edita imagens — use OpenAI gpt-image-2.5-flare/-sunburst, Gemini gemini-nano-banana-2.1, Stability etc.

Best practices para PDF

  • Coloque PDFs antes do texto no array content.
  • Use fontes padrão; rotacione páginas para cima; garanta legibilidade.
  • Use números de página do PDF viewer nos prompts ("na página 12, …").
  • Particione PDFs muito grandes em seções.
  • Habilite prompt caching com cache_control: { type: "ephemeral" } no bloco document para queries repetidas.
  • Em jobs em batch, use client.messages.batches.create({...}) — mesmos blocos, 50% de desconto, SLA 24h.

7.4 Office / Excel / CSV ¶

A Messages API tem três caminhos diretos para documentos não-PDF:

  1. Inline como texto (bloco text) — recomendado para CSV/TXT/MD pequenos.
  2. Upload como documento Files API (source.type=file) — para PDF e text/plain.
  3. Mount no sandbox via container_upload — para XLSX, DOCX, PPTX, CSVs grandes.

1. Inline como bloco text (CSV/TXT/MD)

Caminho mais barato e rápido para documentos estruturados pequenos: cole as primeiras linhas num bloco text (por exemplo, "\n".join(",".join(r) for r in rows[:200])). Não preserva formatos binários (XLSX, DOCX, PPTX) — esses exigem pré-extração ou Code Execution.

2. Upload como Files API document

A Files API trata dois MIME types como blocos document:

MIMEBlocoUso
application/pdfdocumentAnálise visual + textual do PDF
text/plaindocumentAnálise textual sem inlining
Para DOCX com imagens, a doc recomenda converter para PDF primeiro e usar o caminho de PDF — assim você mantém parsing de imagens e suporte a citations.

3. Mount no sandbox de Code Execution (container_upload) — XLSX/DOCX/PPTX/CSVs grandes

Suba o binário pela Files API e referencie em um bloco container_upload junto do tool code_execution_20260521. Claude pode então import pandas as pd; pd.read_excel("/mnt/user-data/..."), rodar pivots, gerar gráficos e devolver outputs. As libs pré-instaladas — openpyxl, xlrd, python-docx, python-pptx, pypdf, pdfplumber, tabula-py — cobrem todos os formatos Office canônicos. 

import anthropic

client = anthropic.Anthropic()
with open("Q1.xlsx", "rb") as f:
    up = client.files.upload(file=("Q1.xlsx", f,
        "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet"))

resp = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=8192,
    messages=[{"role": "user", "content": [
        {"type": "text", "text": "Build a pivot of revenue by product family and export to CSV."},
        {"type": "container_upload", "file_id": up.id},
    ]}],
    tools=[{"type": "code_execution_20260521", "name": "code_execution"}],
)
print("".join(b.text for b in resp.content if b.type == "text"))
DOCX → PDF: para apresentar um DOCX rico em imagens ao modelo com visão, converta para PDF antes e use o caminho de document. Para extração tabular simples, ler o DOCX no sandbox e gerar CSV é mais barato.

7.5 Code Execution ¶

O que é

Runtime Python + Bash server-side sandboxado que a Anthropic provisiona por workspace. Claude planeja, escreve, roda e itera código; monta seus arquivos da Files API; produz gráficos, CSVs e ZIPs; e devolve novos file_ids que você baixa. A versão atual do tool expõe dois sub-tools que Claude chama automaticamente:

  • bash_code_execution — comandos shell (instalar pacote, file ops, qualquer POSIX).
  • text_editor_code_execution — view, create, str_replace, insert em arquivos.

Versão do tool

Use code_execution_20260521 (GA, sem cabeçalho anthropic-beta) em Fable 5.1, Mythos 5.1, Opus 5.5, Sonnet 5.5 e Haiku 5.5. A descrição da tool informa o limite de 90 s por célula Python no tool calling programático. Para computer use, a tool é computer_toolset_20260801. Fonte: code-execution-tool#tool-versions.

Runtime do sandbox

Python 3.11 em container Linux x86_64, 5 GiB de RAM, 5 GiB de workspace, 1 vCPU, sem rede outbound; acesso a arquivos só no diretório de workspace; container vinculado ao workspace da API key e válido por 30 dias após a criação.

Bibliotecas pré-instaladas (lista oficial): pandas, numpy, scipy, scikit-learn, statsmodels, matplotlib, seaborn, pyarrow, openpyxl, xlsxwriter, xlrd, pillow, python-pptx, python-docx, pypdf, pdfplumber, pypdfium2, pdf2image, pdfkit, tabula-py, reportlab, Img2pdf, sympy, mpmath, tqdm, python-dateutil, pytz, joblib e utilitários (unzip, unrar, 7zip, bc, rg, fd, sqlite). Outras libs só entram se você fizer stage dos wheels antes, porque a rede outbound é bloqueada.

File input — container_upload

Para montar um arquivo da Files API dentro do sandbox, envie um bloco container_upload referenciando o file_id, junto do tool code_execution_20260521. Dentro do sandbox o arquivo aparece no workspace. Arquivos que Claude escreve voltam como file_ids aninhados em bash_code_execution_tool_result.content.content[]; baixe-os pela Files API. Passe container=<id> (de resp.container.id) na próxima request para reusar o sandbox por até 30 dias.

import anthropic

client = anthropic.Anthropic()
up = client.files.upload(file=open("sales.csv", "rb"))

resp = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=8192,
    messages=[{"role": "user", "content": [
        {"type": "text", "text": "Plot monthly revenue as a line chart and save as output.png."},
        {"type": "container_upload", "file_id": up.id},
    ]}],
    tools=[{"type": "code_execution_20260521", "name": "code_execution"}],
)

for item in resp.content:
    if item.type == "bash_code_execution_tool_result" and item.content.type == "bash_code_execution_result":
        for f in item.content.content:
            meta = client.files.retrieve_metadata(f.file_id)
            client.files.download(f.file_id).write_to_file(meta.filename)

Erros

Os códigos vêm dentro de *_tool_result_error: unavailable, execution_time_exceeded, container_expired (mais de 30 dias), invalid_tool_input, too_many_requests; no bash, output_file_too_large; no text editor, file_not_found e string_not_found. Turnos longos podem terminar com stop_reason="pause_turn": devolva a resposta inalterada para continuar.

Pricing do Code Execution

  • Free quando usado junto de web_search_20260318 ou web_fetch_20260318 — sem custo por execução, apenas tokens normais.
  • Sem essas tools: cobrado por tempo de execução por container, mínimo de 5 minutos por sessão; 1.550 horas grátis por organização por mês, depois $0.05 por hora, por container.
  • Se há blocos container_upload, o tempo é cobrado mesmo que Claude nunca invoque o tool, porque os arquivos são pré-carregados.
  • Uso aparece em response.usage.server_tool_use.code_execution_requests; a Batches API tem o mesmo preço.
  • ZDR: Code Execution não é elegível para ZDR. Dados do container (uploads e outputs) são retidos por até 30 dias.

7.6 Vídeo ¶

Estado atual

Claude não ingere vídeo nativamente na Messages API: não há content block video; a documentação de vision e de PDF cobre apenas imagens e PDF. Entrada de vídeo não está documentada em platform.claude.com.

Workaround recomendado — frame extraction

Sub-amostre o vídeo em frames estáticos (tipicamente 0.5–2 FPS dependendo do movimento) e envie como sequência de blocos image; cabem até 600 imagens por request. 

# ffmpeg -i input.mp4 -vf fps=1 frames/frame_%04d.jpg
import base64, glob, anthropic

client = anthropic.Anthropic()
content = [{"type": "text", "text": "These are frames at 1 FPS from a short clip. Summarize what happens."}]
for i, path in enumerate(sorted(glob.glob("frames/frame_*.jpg"))[:60], 1):
    b64 = base64.standard_b64encode(open(path, "rb").read()).decode()
    content.append({"type": "text", "text": f"Frame {i}:"})
    content.append({"type": "image", "source": {"type": "base64", "media_type": "image/jpeg", "data": b64}})

msg = client.messages.create(model="claude-opus-5-5", max_tokens=2048,
                             messages=[{"role": "user", "content": content}])
print(msg.content[0].text)

Em vídeos longos, envie os frames uma vez pela Files API e referencie por file_id. Para a fala, transcreva o áudio externamente (gpt-transcribe, gemini-3.5-transcribe) e prefixe o transcript como bloco text antes dos frames.

7.9 Prompt caching com imagens / PDFs ¶

O prompt caching da Anthropic permite marcar conteúdo de prefixo caro (system prompt, imagens grandes, PDFs grandes) com cache_control para que requests subsequentes que baterem no mesmo prefixo paguem uma tarifa reduzida de cache-read.

Uso

Anexe cache_control: { type: "ephemeral", ttl: "5m" | "1h" } em um bloco image, document, text, definição de tool, ou tool result. Ordem importa — a Anthropic cacheia prefixos, então coloque conteúdo estável (system → tools → docs grandes → imagens) antes do turno dinâmico do usuário. 

msg = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": [
        {"type": "document",
         "source": {"type": "base64", "media_type": "application/pdf", "data": pdf_b64},
         "cache_control": {"type": "ephemeral", "ttl": "1h"}},
        {"type": "text", "text": "Which model has the highest win rate?"},
    ]}],
)
# msg.usage.cache_creation_input_tokens / cache_read_input_tokens

Constraints

  • Até 4 breakpoints cache_control por request.
  • TTL: "5m" (default) ou "1h".
  • Cache é chaveado por prefixo: qualquer mudança mais cedo no prefixo invalida tudo o que vem depois.
  • Tamanho mínimo cacheável: 512 tokens em todos os modelos atuais. Abaixo disso o cache não é criado, nenhum erro é retornado e você paga input cheio. Com 512 tokens, um screenshot único ou um PDF de 1–2 páginas já podem ser cacheados. Fonte: prompt-caching#cache-limitations.
  • Multiplicadores: write 5m = 1,25× o input base; write 1h = 2×; read = 0,1× no Haiku 5.5, 0,05× no Opus 5.5 e no Sonnet 5.5, 0,025× no Fable 5.1. Opus 5.5 ($4/MTok): write 5m $5 · write 1h $8 · read $0,20. Sonnet 5.5 ($2/MTok): read $0,10. Fontes: pricing e models/overview.
  • Image caching: bytes da imagem + representação tokenizada são cacheados — modelos hi-res (Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.1) são quem mais ganha.
  • PDF caching: cada página é cacheada como image + text tokens — economia escala linearmente com o doc.

Quando compensa

  • Mesmo PDF, muitas perguntas (Q&A estilo analista).
  • Mesmo screenshot, muitos prompts diagnósticos.
  • Documento de referência grande sendo chunked em muitos turnos.
  • Loops de tool use repetidos onde o schema do tool é grande.

7.11 Limitações & gotchas ¶

Visão

  • Sem identificação de pessoas, sem conteúdo que viola AUP, sem diagnóstico CT/MRI.
  • Artefatos de compressão lossy podem quebrar OCR — verifique seu downscaler.
  • Coordenadas retornadas pelo modelo referem-se à imagem pós-resize e pós-pad. Reescale antes de desenhar no original.
  • Imagens via base64/URL são efêmeras; descartadas após a response. Para "lembrar" entre turnos, use Files API com o mesmo file_id.
  • Animações: apenas o primeiro frame de GIF/WebP.

PDF

  • Sem PDFs com senha/encriptados.
  • Teto de 600 páginas (modelos de 1M de contexto, todos os atuais) — mas request size (32 MB) e context window podem bater antes.
  • Cada página é texto + imagem; PDFs de 100 páginas podem consumir 200k+ tokens facilmente.

Code Execution

  • Sem rede outbound. Qualquer pip install ou urllib.request.urlopen falha. Pré-instaladas cobrem a maior parte; para o resto, stage wheels via container_upload.
  • Container expira em 30 dias; container_id serve para workflows curtos, não storage durável.
  • Sessões concorrentes são cobradas por container — 10 containers paralelos × 10 min = 10 × min(5 min, real).
  • Bash output_file_too_large trip em stdout multi-MB (ex.: imprimir DataFrames inteiros). Pipe para arquivo e baixe.
  • Code Execution não é ZDR-elegível.

Files API

  • 500 MB por arquivo, 1 TB por org. No teto de org os uploads retornam 403.
  • Rate limit aproximado de 500 RPM. Não é bus de ingestão high-volume.
  • Arquivos enviados não podem ser baixados. Apenas arquivos que Claude produziu (skills ou Code Execution) têm downloadable: true.
  • Arquivos persistem até serem deletados — limpe periodicamente ou veja o storage encher.
  • Escopo de workspace: qualquer API key do mesmo workspace pode usar/deletar qualquer arquivo. Trate como compartilhado.

Geral

  • Blocos multimodais contam para o mesmo limite de 32 MB por request; muitas imagens grandes → Files API.
  • Blocos image e document só existem dentro de mensagens com role: "user".
  • O chain-of-thought do modelo (quando thinking está habilitado) não faz streaming da imagem. Não espere "ver" Claude olhando a imagem passo-a-passo em adaptive thinking.
  • tool_choice forçado: any/tool devolve 400 em Opus 5.5, Sonnet 5.5 e Fable 5.1; use auto com strict: true ou structured outputs. O Haiku 5.5 aceita tool_choice forçado (a resposta não traz bloco thinking). Nada disso afeta os blocos image/document.

8. Receitas práticas ¶

Padrões resolvidos lado a lado nos três providers. Cada cartão traz o problema e snippets compactos por API; os blocos extensos ficam em <details>. Gemini usa a Interactions API, exceto onde a receita marca o uso exclusivo do generateContent.

R1 — Q&A em PDF longo com citações por trecho

Problema: usuário sobe um PDF de centenas de páginas e quer respostas com o trecho exato citado. Apenas a Anthropic tem primitiva de citação nativa no bloco do documento; a OpenAI usa as annotations do File Search; no Gemini a citação vem do prompt.

OpenAI File Search + Responses (annotations) 
from openai import OpenAI
client = OpenAI()

# 1) Criar vector store e anexar o PDF (purpose user_data)
vs = client.vector_stores.create(name="kb")
up = client.files.create(file=open("manual.pdf", "rb"), purpose="user_data")
client.vector_stores.files.create(vector_store_id=vs.id, file_id=up.id)

# 2) Perguntar com a tool file_search; include devolve os trechos recuperados
resp = client.responses.create(
    model="gpt-6-astra",
    tools=[{"type": "file_search", "vector_store_ids": [vs.id]}],
    include=["file_search_call.results"],
    input="Quais cláusulas tratam de rescisão? Cite o trecho.",
)
for item in resp.output:
    for part in getattr(item, "content", None) or []:
        for ann in getattr(part, "annotations", None) or []:
            if ann.type == "file_citation":
                print(ann.file_id, ann.filename)

Detalhe completo em §4.3 e §4.8. A citação devolve arquivo e posição; o texto do trecho está em file_search_call.results.

Gemini PDF nativo + prompt para citar 
from google import genai
client = genai.Client()

f = client.files.upload(file="manual.pdf")  # PDF: até 50 MB
interaction = client.interactions.create(
    model="gemini-3.8-flash",
    input=[
        {"type": "document", "uri": f.uri, "mime_type": "application/pdf"},
        {"type": "text", "text": "Quais cláusulas tratam de rescisão? "
                                 "Responda citando o nº da página e o trecho literal entre aspas."},
    ],
)
print(interaction.output_text)

O nº da página vem do próprio modelo, não de um campo estruturado. Ver §6.3.

Anthropic citations.enabled: true (nativo) 
import anthropic, base64

client = anthropic.Anthropic()
pdf_b64 = base64.standard_b64encode(open("manual.pdf", "rb").read()).decode()
msg = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": [
        {"type": "document",
         "source": {"type": "base64", "media_type": "application/pdf", "data": pdf_b64},
         "citations": {"enabled": True}},
        {"type": "text", "text": "Quais cláusulas tratam de rescisão?"},
    ]}],
)
for block in msg.content:
    if block.type == "text":
        for c in (block.citations or []):
            print(c.cited_text, "→ pg", c.start_page_number)

Único com citações estruturadas no payload — ver §7.3.
