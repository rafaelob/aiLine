# Claude API — per-model capability matrix

Split out of `claude-api/SKILL.md` on 2026-07-28 to fit the 5k-token L2 body cap. The entries
are verbatim; the HTTP-400 traps they describe are also summarized inline in the skill's
`## Gotchas`, so the body still warns without carrying the tables.

**Perishable.** Every row here is a per-model fact that expires on a model release. Verify at
`platform.claude.com/docs/en/about-claude/models/overview` before relying on any of it.

- **New tokenizer on Opus 4.7+, Sonnet 5, Fable 5, and Fable 5.1** — produces ~1.0–1.35× more tokens (up to ~30% worst case) for the same text compared to pre-4.7 models (Opus 4.6 and Sonnet 4.6 keep the old tokenizer). Account for this in context window planning and cost estimates; re-baseline `max_tokens` when migrating Sonnet 4.6 → Sonnet 5
- **output_config.effort parameter** — `output_config={"effort": "low"|"medium"|"high"|"xhigh"|"max"}` controls reasoning depth (with adaptive thinking) and general output verbosity. `max` is the true ceiling (not `xhigh`). Fable 5.1, Opus 5, Opus 4.8, and Sonnet 5 support all five levels including `xhigh` and `max` (on Opus 5 specifically, `xhigh`/`max` also blocks `thinking:{"type":"disabled"}` — see the thinking-mode table above); Fable 5 supports `low`/`medium`/`high`/`xhigh`/`max`; Sonnet 4.6 supports `low`/`medium`/`high`/`max` (no `xhigh`); Haiku 4.5 does not support `effort`. When left unset, `effort` defaults to `high` on the Claude API and Claude Code for Opus 5 and Sonnet 5, and to `high` on all surfaces (API, Claude Code, claude.ai) for Opus 4.8 (confirmed at https://platform.claude.com/docs/en/about-claude/models/overview, 2026-09-04)
- **Thinking modes differ per model** — Adaptive-only: Fable 5.1, Fable 5, Sonnet 5 (on by default), Opus 5, Opus 4.8, and Opus 4.7 (`enabled` returns 400; on Opus 5 only, `disabled` itself also returns 400 above `effort` `high`). Both modes (adaptive recommended, `enabled` deprecated): Opus 4.6 and Sonnet 4.6. Enabled-only (no adaptive): Haiku 4.5, Opus 4.5, Sonnet 4.5.
- **`budget_tokens`/enabled mode is DEPRECATED on Opus 4.6 and Sonnet 4.6** (still functional but will be removed in a future model release — migrate to `{"type": "adaptive"}`). On Fable 5.1, Fable 5, Sonnet 5, Opus 5, Opus 4.8, and Opus 4.7, enabled mode returns a 400 error — use adaptive mode only.
- **Fast mode (research preview, Claude API only)** — `speed:"fast"` on Opus 5 and Opus 4.8 costs $10/$50 per MTok (2x standard pricing). **Opus 4.7 fast mode was removed**: `speed:"fast"` on `claude-opus-4-7` now returns an error instead of silently falling back to standard speed (the Opus 4.6 behavior) — do not rely on a silent fallback when migrating 4.7 code.
- **Two new betas (2026-07-24)** — `mid-conversation-tool-changes-2026-07-01`: add/remove tools between turns while preserving the prompt cache; valid on Fable 5, Mythos 5, Opus 4.8, and Opus 5 — **not valid on Sonnet 5**; requires the beta header. `fallbacks` parameter gained mode `"default"` (Anthropic-recommended fallbacks per refusal category) under header `server-side-fallback-2026-07-01`; the older `server-side-fallback-2026-06-01` header only accepts explicit fallback lists. Both remain beta.
- **Claude Fable 5.1** — uses the newer tokenizer, supports all five `output_config.effort` levels with default `high`, and has always-on adaptive thinking. Manual `thinking` modes `enabled` and `disabled` return HTTP 400; use `effort` to control depth. Native structured outputs are supported, but forced `tool_choice` values `any` and `tool` return HTTP 400. Verify current details at https://platform.claude.com/docs/en/models/fable-5-1/overview.
